## Architecture facts (verified)

- `flavors.waleeds.world` = **push-to-deploy**: deployed bytes == `HEAD` commit, built from
  `github.com/Majboor/bookmarklet-flavors` via Cloudflare. Nothing needs to run locally; the
  cloudflared tunnel on this Mac (PID 4740) is unrelated.
- `serve.py` on :8899 is local preview only, not the origin.
- Custom flavors already persist in `localStorage` and run via `new Function(cf.code)` — the
  generated-flavor store is an extension of this, not a new mechanism.

## What the hanzi-browse repo actually contained

Searched all **412 files**, not just the skills. Total selector haul: **one** —
`[data-testid="tweetTextarea_0"]` in the x.com entry of `server/dist/agent/domain-skills.json`.
The 21 domain entries there are behavioural guidance ("click the post title", "comments are
nested", "Draft.js ignores programmatic input"), which is useful for knowing *what* to look for
but cannot seed a memory file. It did confirm that **X's durable handle is `data-testid`**.

| **B9** | Trusted Types killed every generated flavor | ✅ | The **executor** was the bug: `runCustomFlavor` used `new Function`, itself a Trusted Types sink, so on YouTube every flavor died at toggle-on with *"Refused to evaluate a string as JavaScript"*. `runFlavorCode` now falls back to injecting a `<script>` with `.textContent` via a TT policy, wrapping in an IIFE because flavor code uses top-level `return` (legal in `new Function`, illegal in a script). Proven on Chromium + WebKit by forcing the real error. ⚠️ Requires **reinstalling the bookmarklet** — the hybrid loader embeds a frozen copy. |
| **B10** | Whole site down: "Could not load flavors" | ✅ | `serve.py` used single-threaded `socketserver.TCPServer`; Cloudflare holds connections open, so one stalled client blocked everything and the accept queue filled (Recv-Q pegged at backlog 5). Process still "listening", systemd still green, every static path timing out. Now `ThreadingHTTPServer`, queue 128, 30s handler timeout. Verified with 24 concurrent requests, all 200. |
| **B11** | Banned-sink filter missed `new Function` | ✅ | The server rejected `innerHTML`/`eval(`/`document.write` but **not `new Function`** — the exact sink that broke a flavor. Now also blocks `new Function`, `Function("...")`, and string-argument `setTimeout`/`setInterval`, while still allowing `setTimeout(function(){})` and `textContent`. |
| **B12** | Silent no-op flavors | ✅ | **Solved by the self-heal loop (A12).** Every flavor is now measured on apply: selectors probed, computed styles fingerprinted before/after. The panel reports "✅ applied — 22 style changes across 9/10 selectors" or "❌ matched nothing". Rule #2 is now enforced by the product, not by memory. |
| **A11** | GLM prompt carries all findings | ✅ | Rewritten from a short list to the full rule set: complete Trusted Types sink list, prefer one `<style>` element, never invent selectors, selectors are page-scoped, never target obfuscated class names, never hide a shared ancestor, **never force `display` on an element you're only restyling** (the thumbnail-vanishing bug), real fullscreen only, SPA re-apply with listener cleanup, null guards, no network/credential access. |

| **A12** | **Self-heal loop** | ✅ | Generation is no longer one-shot. **1) Probe first:** before generating, the client runs every selector in the memory file against the live page and hands the model the counts — ground truth that overrides the memory file, and the only way to see logged-in pages. **2) Verify:** after applying, it fingerprints computed styles of the targeted elements before/after and decides whether anything measurably changed. **3) Repair with history:** if nothing changed, the failure evidence (which selectors matched 0, which were invalid, whether it threw) goes back to `/api/repair`, which replays every prior attempt as real conversation turns so the model cannot re-propose a selector it already proved dead. Up to 3 rounds. **4) Learn:** `/api/observe` records real selector counts per domain and feeds them into later prompts, so the memory improves by itself from real sessions. Verified live on YouTube: 22 style changes across 9/10 selectors, 0 repairs needed; and a forced-failure repair dropped all 3 dead selectors and switched to the measured-live ones. |
| **B13** | Selector extractor ate JS source | ✅ | `extractSelectors` sliced multi-line array literals into fragments like `"[\n  '#secondary"` and reported them to the model as invalid selectors *it* had written — sending it chasing its own tail. Now rejects anything containing quotes/newlines, unbalanced brackets or parens, and validates each candidate with a real `querySelector` before accepting it. |

| **B14** | Chat refine replied but changed nothing | ✅ | `renderChatView`'s Send called `saveGenerated` — storing the new code but **never running it**. With the flavor already on, the old code stayed applied, so the model's reply updated while the page sat unchanged. Send now undoes the previous version first (otherwise the new code lands on top of the old styles, or worse reuses the same sentinel id and *removes* it), then runs the full verify/repair loop and reports the verdict. Verified live: refine hid sidebar **and** comments, 7 style changes, 0 repairs. |
| **B15** | Verifier false-negative | ✅ | The selector extractor rejected any candidate containing a quote or newline — but a rule head sliced out of JS carries the string delimiter (`'#secondary`, `` `\n#secondary ``), so real selectors were silently dropped. The verifier then saw no targets, reported "matched nothing" on a flavor that visibly worked, and burned 3 repair rounds fixing nothing. Now strips delimiters, collapses newlines (legal in descendant selectors) and lets `querySelector` be the gate. All extractor cases pass; the same flavor now reports `worked=True, repairs=0`. |

| **B16** | Static site dying repeatedly | ✅ | **Port collision, not connection handling.** `serve.py` sat on **8899** — the Inverex/Deye solar dongle port — so `poller_solar.py` sprayed binary Modbus-ish frames at the web server thousands of times a second. Every frame logged: ~170,000 journald lines/min, 12 GB of `/var/log`, root disk at 98%, accept queue starved. Moved to **8898**, tunnel repointed, 8899 returned to the solar poller. Also stopped per-request journald logging, capped journald at 500 MB, vacuumed 2.2 GB. Log volume 170k/min → **5/min**, Recv-Q → 0, 24 concurrent requests all 200. |

| **A13** | **Context layer: SITE → CONTEXT → INTENT → MODE** | 🟡 | Answers *"what are you here for"* rather than *"what is noisy here"* — the question a prompt box can never ask, because the user would have to know to type it. jev gets the site, the local clock and the cross-site trail. Verified: Thu 14:00 after API searches → **learning** → Study Mode; Fri 23:30 after stand-up → **entertainment** → Lean-back Mode; Wed 02:00 after GitHub+Sentry → **working** → Answer Mode; Upwork bidding → **job_hunting**, correctly **silent** because no verified Mode exists. Confident reads act; ambiguous ones ask **one short question** ("Studying or working?") and the answer is remembered per site **and time bucket**. A Mode is a hand-written, named transformation for one (context, site) pair — the model picks which Mode fits, it never invents the transformation. **Needs:** live browser test of the whole flow. |
| **B17** | Trail could only see its own site | ✅ | `localStorage` is origin-scoped, so the client trail on youtube.com contained only youtube.com — verified by measuring it. The cross-site premise silently degraded to "how many pages on this one site", which looks like it works. Trail moved server-side, keyed by a salted hash of the client IP, hostnames only, in memory, 30-min TTL, never written to disk. Measured effect: same scenario went from confidence **0.67 (had to ask)** to **0.85 (acts)**. |
